# Timestamp в API

Все исходящие с фронта timestamp-поля (`start_at`, `end_at`, `updated_at` и т.п.) приходят в формате **ISO 8601 с явным смещением таймзоны пользователя**, например:

```
2025-01-25T14:00:00.000+05:00
```

По ним можно определить и момент времени, и таймзону, в которой пользователь внёс изменение.

---

## Ответы бэкенда

**Все** поля с датой/временем с бэка приходят **всегда в формате ISO 8601 с таймзоной** (с `Z` или offset, например `2025-01-25T09:00:00.000Z` или `2025-01-25T14:00:00+05:00`):

- `*_at` (`created_at`, `updated_at`) — во всех сущностях;
- `start_at`, `end_at` — в событиях, bagsies;
- `open`, `close` в `ISchedule` (расписание пользователя, точки);
- `from`, `to` в ответах, связанных с расписанием.

Фронт парсит их через `parseTimestamp` и `parseScheduleTime` и при отображении конвертирует в локальную таймзону/время.

---

## Schedule (расписание)

Поля **`from`/`to`** (PUT `/v1/users/me/schedule`) и **`open`/`close`** (в `ISchedule` при создании точек и в ответах) — время суток (recurring по дням недели).

- **На бэк** фронт шлёт **ISO 8601 с таймзоной**; для времени суток используется опорная дата `1970-01-01`, например:
  - `1970-01-01T09:00:00.000+05:00` — 09:00 в таймзоне пользователя
  - `1970-01-01T18:00:00.000+05:00` — 18:00
- **С бэка** `open`/`close` (и при необходимости `from`/`to` в ответах) приходят **всегда в ISO 8601 с таймзоной**.
